# Contributing

## Before creating an issue

1. Confirm the source is relevant to Apple platform engineering.
2. Search existing issues for the same observable failure mode.
3. Prefer authoritative Apple sources where available.
4. Separate confirmed facts from reproduction results and inference.

## Required issue content

- Source
- Problem
- Solution / Guideline

## Evidence discipline

Use one of these evidence levels:

- Apple Confirmed
- Reproduced
- Inferred

If a conclusion comes from reverse engineering, logs, experiments, or decompiled behavior, label it as inferred unless Apple documents or confirms it.

## Writing style

- State the observable problem first.
- Keep the issue engineering-focused.
- Prefer exact APIs, error codes, OS versions, and reproduction conditions.
- Avoid speculative language in the Solution / Guideline section.
- Make verification steps executable by another engineer.
